# Ernest v0.2.0-alpha

Ernest `v0.2.0-alpha` turns the alpha PoC into a system an external auditor can
actually distrust productively: scoped access for reviewers, evidence receipts
verifiable offline against the public chain, a cross-language hash consensus pinned
in CI, and integrity monitoring that scales past PoC-sized chains.

Full change list: [CHANGELOG.md](../../CHANGELOG.md).

## Highlights

### Access control for the auditor story
- Read-write vs. read-only keys (`ERNEST_API_KEY` / `ERNEST_READ_API_KEY`), enforced
  globally.
- Named, revocable, optionally expiring access tokens (SHA-256-hashed at rest),
  issued and revoked from `/settings/tokens` — hand an external auditor their own
  credential instead of a shared secret.
- A real `/login` page; write actions disable under read-only credentials.

### Evidence receipts (SPV-style inclusion proofs)
- `GET /api/blocks/:index/proof` emits a self-contained receipt: block, ~log2(N)
  Merkle proof path, anchored root and anchor transaction.
- Verify it anywhere: `ernest proof verify receipt.json` (CLI, offline) or the new
  `/verify-receipt` page — entirely in the browser via WebAssembly (`merkle-wasm`),
  nothing leaves the auditor's machine.
- The endpoint refuses to emit receipts when local history no longer reproduces the
  anchored root; the refusal is itself tamper evidence.

### One hash law, four implementations, pinned in CI
- `testdata/hash-golden-vectors.json` and `testdata/merkle-proof-golden.json` hold
  the NestJS backend, Go event-writer, Go CLI and Rust/WASM verifier to
  byte-identical canonicalization and proofs. Any drift — including a dependency
  upgrade changing behavior — fails CI instead of silently forking the chain.
- The Go writer was conformed to RFC 8785 (no HTML escaping, ECMAScript number
  notation, UTF-16 key order) and now rejects integers beyond 2^53 at ingest.

### Verification and export that scale
- The hourly integrity check is checkpointed: O(new blocks) incremental passes, an
  every-run re-validation of the latest anchored Merkle root, and a daily full
  re-scan (`INTEGRITY_FULL_SCAN_HOURS`).
- `GET /api/blocks/export` streams with constant memory; the CLI verifies the chain
  through the read-only API (`--api`) or an offline export (`--file`) — no database
  credentials required.

### Correctness fixes worth reading
- Concurrent model registration is serialized before touching the hashchain;
  inference blocks can no longer precede their model's registration block.
- Block timestamps are monotonic in both writers.
- The event-writer no longer crash-loops on Mongoose-named indexes; the CLI verifier
  no longer verifies against empty block data; `PATCH /api/models/:id/status` is
  write-guarded.

## Alpha Limitations

- Not a production compliance system.
- Access control is key/token-based; per-client enterprise identity (OIDC/SSO) and
  signed client submissions are future milestones.
- History not yet covered by a confirmed anchor remains rewritable by whoever
  controls the database — see [docs/threat-model.md](../threat-model.md) for the
  full guarantees/non-guarantees analysis.
- Public-chain anchoring requires funded Sepolia credentials and is not exercised
  in CI.
- Browser demo API keys are public in the frontend bundle and are not production
  secrets.
